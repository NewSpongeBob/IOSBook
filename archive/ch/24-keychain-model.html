Keychain 与凭据生命周期

可访问性与访问组决定凭据在什么状态下可用、能被谁共享

把令牌放进钥匙串只是第一步。真正决定安全与可用性的是三个属性：谁能读（访问组）、什么时候能读（可访问性）、换设备后还在不在（同步与“仅本设备”）。

1. 条目模型

  • 类型：通用密码、互联网密码、密钥、证书等，类型决定可用属性集合。
  • 标识：服务名与账号名组成常用查询键。
  • 访问组：限定哪些签名主体可以共享，缺失或不匹配时返回权限错误。
  • 可访问性：决定设备锁定状态下的可用性，可附加生物识别保护。

2. 可访问性选择

属性可用条件适用与代价
解锁后可访问设备已解锁最常用；后台任务读不到，需处理失败
首次解锁后可访问本次启动解锁过一次后台刷新可用，暴露面稍大
仅本设备（配合解锁）已解锁，且不随备份迁移换机需重新登录
需生物识别 / 需当前生物特征集合用户通过生物识别高价值操作；录入新指纹/面容后旧条目可能失效

“需要生物识别”不是“更安全就好”的默认选项：它会让后台刷新、自动续期一类流程无法读取凭据。选型要跟业务流程对齐。

3. 写入与更新

钥匙串接口没有“插入或更新”的单一调用。常见错误是重复添加导致 errSecDuplicateItem，或者先删后加在失败时丢数据。稳妥做法是先尝试更新，缺失时再添加：

Swift：先更新后添加
let query: [String: Any] = [
    kSecClass as String: kSecClassGenericPassword,
    kSecAttrService as String: service,
    kSecAttrAccount as String: account
]
let attrs: [String: Any] = [kSecValueData as String: data]

let status = SecItemUpdate(query as CFDictionary, attrs as CFDictionary)
if status == errSecItemNotFound {
    var add = query
    add[kSecValueData as String] = data
    add[kSecAttrAccessible as String] = kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly
    let addStatus = SecItemAdd(add as CFDictionary, nil)
    // 处理 addStatus，特别是 errSecMissingEntitlement
}

4. 常见问题清单

  • 用偏好设置存令牌：无加密、随备份扩散、易被日志带出。
  • 忽略 errSecInteractionNotAllowed：后台或锁屏读取“解锁后可访问”条目时的典型错误，应按“稍后重试/需要用户操作”处理。
  • 卸载重装后仍有旧数据：钥匙串条目可能保留，首次启动应主动清理或校验归属。
  • 不处理生物特征变更：用户新增指纹后“需当前生物特征集合”的条目失效，需引导重新认证。
  • 访问组配置与签名不一致：扩展与主应用读不到同一条目。

5. 可验证实验

  1. 写入一条“解锁后可访问”的条目，锁屏后在后台读取，记录返回状态码并实现对应的降级。
  2. 把同一条目分别以不同可访问性写入，比较重启、锁屏、备份恢复后的行为。
  3. 为自己构建的应用添加生物识别保护，录入新的生物特征后再读取，观察条目状态变化。
