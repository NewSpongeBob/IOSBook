S02

密钥、凭据与数据保护

客户端保管不了长期秘密，能做的只有缩短暴露与减少副本

“把密钥藏进客户端”不是密钥管理，只是延迟被发现的时间。可靠的设计是：长期秘密留在服务端，客户端只持有短期、可撤销、范围受限的凭据，并用平台机制保护它。

1. 数据分级决定存储位置

级别示例建议位置
公开静态配置、帮助文本随包资源
内部功能开关、缓存的列表容器文件，可重建
用户私有个人资料、聊天记录容器文件 + 文件保护
凭据访问令牌、刷新令牌钥匙串，限定可访问性
高价值秘密服务端主密钥、支付密钥只存在于服务端

2. 密钥从哪来

  • 短期令牌：服务端签发，带有效期与权限范围；客户端刷新时使用受限的刷新凭据。
  • 设备本地密钥：在设备上生成对称密钥并存入钥匙串，用于加密本地数据，不参与服务端身份验证。
  • 不可导出密钥：能使用安全隔区时，让密钥在隔离区内生成并只暴露操作接口。
  • 不要硬编码：打包进二进制的字符串可被直接读出，无论做多少层混淆。

3. 加密怎么选

使用平台提供的认证加密（如 AES-GCM），不要自创模式或自己拼接“加密 + 校验”。认证加密同时保证机密性与完整性，避免填充预言机一类问题。

Swift CryptoKit：认证加密与解密
import CryptoKit

let key = SymmetricKey(size: .bits256)
let sealed = try AES.GCM.seal(plaintext, using: key, authenticating: aad)
let payload = sealed.combined          // 含 nonce、密文与标签

let box = try AES.GCM.SealedBox(combined: payload)
let opened = try AES.GCM.open(box, using: key, authenticating: aad)

注意 aad（附加认证数据）要覆盖上下文（如用户标识、版本），否则密文可能被搬到别的语境使用。

4. 生命周期

  • 轮换：令牌有有效期，密钥有轮换计划；轮换期间要能同时接受旧新两套。
  • 撤销：注销、改密、设备丢失时由服务端撤销，不能只删本地副本。
  • 清理：切换账号、退出登录要清理本地缓存与钥匙串条目。
  • 备份：高价值数据应排除备份，或明确“仅本设备”语义。

5. 泄漏面清单

位置检查点
日志是否打印请求头、令牌、完整响应体
崩溃报告异常信息是否携带敏感参数
剪贴板复制敏感内容后的清理与提示
界面快照进入后台时是否遮挡
分析事件自定义字段是否包含身份标识
备份哪些文件参与了备份

6. 可验证实验

  1. 在自有应用里写入测试令牌，检查容器文件、偏好设置、日志中是否出现明文。
  2. 把令牌放入钥匙串并设置为解锁后可访问，锁屏后在后台读取，记录失败形态与降级逻辑。
  3. 用认证加密写入一段数据，改动一个字节后解密，确认被拒绝而不是返回错误明文。
