# IOSBook

iOS 系统、运行时与逆向工程的条理化教程。目录按 AndroidBook 的能力阶梯组织：系统与检测 → 内核 → 动态插桩 → 运行时 → 框架 → 加固 → 训练营 → 附录。

## 三条主线

- **可信链**：越狱与启动信任、代码签名、设备证明。
- **运行链**：XNU、dyld、Mach-O、ARM64 调用约定、Objective-C / Swift 运行时。
- **检测链**：注入与 hook 的观测面、检测信号、兼容与代价。

## 目录结构

```
index.html        首页
nav.js            全书导航数据（唯一数据源：部 → 讲 → 标题 → 顺序）
app.js            侧边栏、面包屑、上一讲/下一讲、部级目录、目录搜索、代码复制
style.css         全站样式
ch/               各讲正文，一讲一个 HTML
part/             各部索引页
assets/figures/   原理图（SVG），按“图 部-序”编号
archive/          已移出正文的旧章节（不参与导航与分页）
404.html          GitHub Pages 自定义 404
.nojekyll         关闭 Jekyll
```

### 约定

- 章节顺序、标题、所属部只写在 `nav.js`。侧边栏、面包屑、分页、部级列表都由 `app.js` 渲染，**不要手写目录**。
- 页面在 `<html>` 上声明 `data-root` 与 `data-page`，`app.js` 据此计算相对链接。
- 一讲有 4 个以上 `h2` 时，自动生成“本讲目录”。
- 正文结构：`p.lead` 导语、`h2` 编号小节、`table` 对照表、`div.code`（含 `.code-title` 与 `.copy`）、`aside.callout` 要点、`details` 折叠。

### 写作规范（每讲最低配置）

- ≥2 张对照表；有机制就有表，避免成段描述
- ≥1 段可复制的命令或代码
- ≥1 个要点框（经验值、反直觉结论或边界）
- 3–4 道机制型自测，考“为什么”而不是复述
- 有真实工具输出时直接引用，并注明来源平台（如 macOS arm64e）
- 过程型机制配“分步图”（16 幅）：页面上可点 1…N 逐步高亮，禁用脚本时退化为整图
- 版本相关结论标注适用条件

## 与 AndroidBook 的关系

- 部级结构对齐：系统与检测 / 内核 / 动态插桩（对应 Frida 详解）/ 运行时 / 框架（对应 LSPosed）/ 加固与混淆 / 训练营 / 附录。
- 讲数 52 对 65，少的 13 讲集中在“iOS 没有对应物”的地方（内核模块、企业壳拆解）与已删除的安全工程内容。
- 单讲节奏一致：导语 → 编号小节 → 对照表 → 可复制命令 → 失败分流 → 自测。
- 方向差异：AndroidBook 给可操作的攻击路径，IOSBook 只在自己构建的应用与设备上做观测，涉及防护只做识别与评估。

删掉的 33 讲（应用安全工程 8、防护与兼容工程 6、产品与平台说明 7、二进制杂项 5、开发向内核 4、逆向冗余 3）已移到 `archive/`，不参与导航。

## 阅读方法

1. 先建模型，再看实现；结论标明设备、系统版本与证据来源。
2. 每讲至少一次可验证实验，区分“公开文档 / 源码观察 / 实测 / 推断”。
3. 动态分析与插桩只针对自有构建、自有设备与公开样本。

## 本地预览

```bash
git clone https://github.com/NewSpongeBob/IOSBook.git
cd IOSBook
python3 -m http.server 8000
```

打开 http://localhost:8000。导航依赖 JavaScript，直接以 `file://` 打开只能阅读正文。
