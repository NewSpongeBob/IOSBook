公开 API、受限 API 与兼容性

依据平台契约设计，而不是把某次观察到的实现当成承诺

公开 API 的文档和可用性注解构成应用开发的主要契约。私有实现细节可能改变、受限或导致审核与兼容性问题，不应成为产品安全或核心功能依赖。

工程方法

  • 从 Apple Developer Documentation 和 SDK 可用性信息确认 API 支持范围。
  • 区分 public API、实现细节、调试接口与授权能力。
  • 使用 availability 检查和明确的降级路径覆盖旧系统。
  • 对关键 API 行为建立自动化测试，而非依赖名称或猜测。

自测

选一个自有应用使用的系统 API，记录其最低系统版本、权限前置条件、错误语义和替代方案；升级 SDK 后重跑兼容测试。
